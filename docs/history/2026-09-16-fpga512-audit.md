## Plain-language connection

Old recording implementation:

`external ADC/recording board → 8 digital data wires → ECP5 capture/framing/buffering → FT600 USB chip → computer daemon → WAV files + plot`

`computer commands → FT600 → FPGA → ADC reset/SPI/stimulation controls`

`FPGA → 4 serial data outputs + clock → optional UWB interface`

Proposed investigation (not an agreed architecture):

`same or revised recording/routing board [confirm] → voltage-correct interface [design] → exact retained Artix FPGA + selected support circuitry → output/MCU/UWB arrangement [open]`

The CP board supplies an FPGA platform; the FPGA_512 repository supplies a concrete recording workload and existing host software. Combining them requires electrical interface design and a source-code port.

## Inconsistencies not to copy as settled facts

- **Rate:** current README + host use 15,625 Hz and 16.5 MB/s. The top header and older golden-bitstream README say 33 MB/s; their build revisions need confirming. Sampling cadence ultimately comes from external `cb_read`, so a 32 MHz clock alone cannot prove the per-electrode rate.
- **Older system overview:** `docs/SYSTEM_OVERVIEW.md` documents another pipeline (`rx_process_mux`, old pinout and frame timing). Do not treat its ~20.2 kHz serial frame calculation as the current ADC sample rate.
- **CRC comments:** `usb_framer.v` header line 11 says data-only CRC, while active logic seeds SYNC/LANE_ID/CYCLE_CNT and covers those fields plus data (lines 63–65,109–112,143–144 and 165 onward). Preserve the active implementation and matched decoder if porting; do not write a new protocol from stale prose.
- **No loss guarantee:** drop reporting is not loss prevention; a saturating 4-bit drop count cannot quantify arbitrarily long overflow exactly. Source comments about zero steady-state drops are not a new hardware acceptance result.
- **No cross-device utilization claim:** ECP5 LUT/RAM percentages and its DP16KD counts do not prove Artix fit. Artix synthesis, BRAM inference, bank planning, timing and clock-domain checks are required.
- **File length:** current recorder writes ordinary RIFF/WAV with 32-bit lengths (`adc_daemon.c` lines 448–462,557–559). At all-channel 16 MB/s, the roughly 4 GiB container limit is around 268 s (~4.5 min). No automatic split is established by these inspected routines; required session duration/file segmentation stays open.
- **No MCU selection proof:** absent from this top-level data path does not establish that a new MCU is unnecessary or identify the lab's intended MCU.

## One-line glossary for the meeting sheet

- **512 channels**: 512 amplifier/electrode positions represented in the host's channel map.
- **8 serial data lines**: eight physical input wires carry those channels over time, 64 positions per wire; not 512 FPGA input pins.
- **4 framed lanes**: logic pairs the eight wires into four streams, each representing 128 channels.
- **132-word USB frame**: 128 data words + 4 overhead words; each transported word is 16 bits, while each ADC sample contains 12 useful bits.
- **ADC signal group**: 24 declared wires including two named spares; 22 excluding those two spares. This remains a source inventory, not a validated minimum, because stimulation/SPI/clocks/resets have functional requirements and `cb_sync` is also unused in this source version.
- **64 KiB FPGA FIFO**: one specific on-chip queue; not total buffering in the complete system. Other FPGA queues, FT600 hardware buffering and computer RAM are separate.

## Tentative 4K expansion: planning scenarios, not agreed hardware

New user steering: eventual **4K channels is tentative**; splitting the work across two FPGAs is a candidate. Use **4K = 4096** for the calculations below. Confirm the exact count with Gerald. The existing repository implements 512 channels; none of these scenarios is validated by its current bitstream.

Assume the same 12-bit sample format, 16-bit transport words and 132/128 frame overhead, with every channel recorded continuously:

\[
R_{\mathrm{framed}}=N\,f_s\,(2\ \mathrm{bytes/sample})\,\frac{132}{128},\qquad
 t_{\mathrm{FIFO}}=\frac{65{,}536}{R_{\mathrm{framed}}}.
\]

| Planning scenario | Samples/s/channel | ADC payload, all channels | Framed rate, whole system | Framed rate per FPGA | 64 KiB FIFO headroom per FPGA |
|---|---:|---:|---:|---:|---:|
| One FPGA, 4096 channels | 15,625 | 768 Mbit/s | 132 MB/s | 132 MB/s | 0.496 ms |
| Two FPGAs, 2048 each | 15,625 | 768 Mbit/s | 132 MB/s | 66 MB/s | 0.993 ms |
| One FPGA, 4096 channels | 31,250 | 1536 Mbit/s | 264 MB/s | 264 MB/s | 0.248 ms |
| Two FPGAs, 2048 each | 31,250 | 1536 Mbit/s | 264 MB/s | 132 MB/s | 0.496 ms |

Decimal MB/s; FIFO capacity 65,536 bytes. Headroom assumes each FPGA retains one unchanged 64 KiB FIFO, initially empty, and that rate reaches it continuously. Excludes all other queues and implementation margins. Splitting the FPGA does **not** reduce the total recording/output rate. No table entry establishes Artix fit, actual USB throughput, or adequate loss tolerance.

### Why this is not just duplicating the present bitstream

- FPGA top explicitly creates **8 deserializers** and **4 framed lane pipelines**: [top lines 309–380](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/adc_4lane_framed/top_4lane_framed.v#L309-L380).
- Shared arbiter has **4-bit lane-valid vector and 2-bit lane selection**, and one 16-bit output word: [arbiter lines 21–42](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/fpga/lane_frame_arbiter.v#L21-L42). It cannot uniquely arbitrate 16 or 32 framed lanes unchanged.
- Wire-format lane ID uses only **two lane bits**, with four bits reserved for drop reporting: [USB framer lines 98–107](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/fpga/usb_framer.v#L98-L107). More lanes require a new hierarchy or format, not merely increasing a loop bound.
- Host fixes `N_CHANNELS=512`, has `lanes[4]`, matches four SYNC words and maps `line*64+amp`: [daemon lines 58–60](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/adc_4lane_framed/adc_daemon.c#L58-L60), [lines 104–110](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/adc_4lane_framed/adc_daemon.c#L104-L110), [lines 330–337](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/adc_4lane_framed/adc_daemon.c#L330-L337), [lines 380–395](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/adc_4lane_framed/adc_daemon.c#L380-L395). Software, channel identity and stream alignment must be extended.
- **An unchanged internal shared path is itself too slow for even the 2048-channel/15,625-Hz case.** One 16-bit word per 32 MHz clock gives at most 64 MB/s before any gaps, below the calculated 66 MB/s framed demand. The top clocks its arbiter/FIFO producer with `cb_clk32mhz`: [top lines 383–415](https://github.com/gt-ic/FPGA_512/blob/767e82528780005cbcb37b3e926197755bac622e/adc_4lane_framed/top_4lane_framed.v#L383-L415). A wider/faster/parallel internal transport or different framing is needed. This is a limit of the unchanged architecture, not a claim that the retained Artix cannot implement another architecture.

### Conditional input-wire estimate

**Only if** each 512-channel group repeats the current eight-data-line interface, 4096 channels would require eight such groups. If one ASIC provides each group, that would mean eight ASICs; the repository does not establish the actual 4K ASIC count. An equal two-FPGA split would receive four groups each.

| Unshared legacy-interface replication | One FPGA, 8 groups | Each of 2 FPGAs, 4 groups |
|---|---:|---:|
| ADC serial data inputs alone | 64 | 32 |
| ADC-side source wires excluding two spare inputs per group (22/group) | 176 | 88 |
| If one FT600 interface per FPGA is retained (+24) | 200 | 112 |

These are conditional counts before power/grounds/programming and optional UWB/MCU signals. The 22/group includes clocks, reset, SPI and stimulation; some may be shared or removed after functional/timing agreement, and one sync input is unused in the present RTL. Shared buses may need select signals and fanout management. This is **not a minimum pin count**.

CP SOM ONE's **76 exported general-purpose signals are a breakout/layout choice, not the package's full I/O limit**. A custom PCB can expose other legal package pins, subject to available pins, bank voltages, dedicated clock pins, escape routing and the exact retained device. Do not infer feasibility from 76 alone or assume the current connectors fit the expanded interface.
