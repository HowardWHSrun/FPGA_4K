What the core contains

  • XC7A100T CSG324: 324 balls, 210 user I/O, 0.8 mm BGA pitch. Exact order code must be selected and checked against the 1.0 V core design.
  • Power: four TPS62135 converter circuits for core, auxiliary, configuration and ASIC I/O rails. Regulator input capacitors C3/C7/C11/C15 have been corrected to 22 µF, 25 V, 1206 parts after a DC-bias review. Rail assignments and physical power delivery still require qualification.
  • Startup: 128 Mbit SPI flash, fixed SPI boot straps (M2:M1:M0 = 001), 32 MHz oscillator and dedicated JTAG.
  • Reference: CP SOM ONE informs the power architecture. Its different FPGA package and routing are not a drop-in design.

Custom electrical interface. Do not connect ordinary HDMI equipment. Contact numbers are physical Type-D contacts; cable continuity, orientation, return current and hot-plug protection need verification.

The XEM8310 receiver assembly will supply the custom cable through a designed carrier/adapter. The proposed carrier branch is 12 V ±5%, with a 0.60 A continuous load limit and a maximum 0.30 m custom cable. Voltage drop, fault protection and hot-plug behavior still require qualification. This does not assert that an unmodified XEM8310 can directly power this board.

The development proposal uses three LVDS data pairs plus one forwarded clock, with 12-bit packed samples. Exact XEM8310 contacts, timing closure, common-mode handling, receiver bias/termination and the target-JTAG bridge still require implementation and verification. Direct DC coupling has no guaranteed allowance for positive cable ground offset at the published transmitter/receiver limits. The module’s own JTAG does not automatically program this target. The 1.8 V rail revision is one option; the XEM8310 also has configurable HD banks that could support a separately verified 3.3 V JTAG bridge for the current core. BOARD_READY is an initialization signal, not a continuous rail monitor. Read the source-backed development architecture.

GERALD’S ORIGINAL ASIC SLIDES

More of the protocol is known.

Slides 14–17 identify each ASIC’s eight data outputs, returned clock, READ and SYNC. They show 1,024 clocks per frame and 16 READ groups. Each group has 16 zero clocks followed by 48 clocks carrying four interleaved 12-bit samples.

Slides 25–28 describe FPGA-to-ASIC SPI CLK, L, R and LATCH, then configuration → STIM_EN → STIM_START → charge balancing after 64 STIM_CLK cycles. L and R are both configuration data outputs.

Two conflicts need clarification.

Stimulation timing: slide 18 says 64 clocks = 2 ms, GUI examples use 32 µs per step, and slides 27–28 label 60 kHz. These are not one agreed timing requirement.

Channel labels: the table in slides 15–17 repeats channels 57 and 49 and omits 50 and 59. We retain the original source and flag the apparent errors; a corrected chip map still needs confirmation.

The slides establish useful behavior, but do not establish ASIC pad limits, a guaranteed sampling edge, reset pulse widths or safe startup defaults.

U01 · ASIC electrical limitsLab / system information

Known: The accepted count is 117. Slides 13–14 and 25–28 show recording/control directions: CLK_IN, resets, SPI L/R/CLK/LATCH and stimulation controls go FPGA to ASIC; CLK_OUT, DATA, READ and SYNC return to FPGA. The underlying table lists 1.5 V nominal supply; that row is hidden by an overlay in the visible slides.

Still uncertain: Guaranteed logic thresholds, output drive, load/leakage, absolute limits and powered-off behavior are absent for the full interface. AC_IN and IMP_TST still lack confirmed functions and directions. A nominal supply is not a guaranteed I/O specification.

Close when: Obtain a versioned ASIC pad specification or designer-approved table for all signal classes; compare limits against the selected FPGA standard and power states.

U02 · ASIC timing and sample formatLab / system information

Known: Slides 15–17 show 32 MHz recording, 1,024 clocks/frame, 16 READ groups, and 16 zero clocks plus 48 payload clocks/group. Samples are bit-interleaved A1 bit 0, A2 bit 0, A3 bit 0, A4 bit 0 through bit 11. Slide 26 specifies four 3-bit DR suffix fields and shows a stream ending at bit 2124.

Still uncertain: Capture edge, setup/hold, delay/skew/jitter limits, ADC numeric coding and pause/restart behavior remain unqualified. The channel table duplicates A49/A57 and omits A50/A59. Full SPI packing is missing. Stimulation timing conflicts: 31.25 us, 32 us/step and 60 kHz; the <200 Hz limit also conflicts with a 5 ms example.

Close when: Obtain a corrected versioned channel map, ADC coding, full SPI serializer/workbook and stimulation timing; approve guaranteed pad timing, then constrain and verify capture against an accepted model and measured waveforms.

U14 · Data packing, USB boundaries and control protocolEngineering work

Known: Each READ group has 16 zero clocks followed by 48 payload clocks (25% padding), carrying interleaved 12-bit samples needing deinterleaving. Three proposed 800 Mbit/s lanes provide 240 MB/s after 8b/10b; packed 12-bit samples fit the arithmetic budget, 16-bit sample padding does not.

U15 · Buffering and data loss during host stallsLab / system information

Known: The proposed four LVDS pairs all travel toward the receiver. USB throttling alone does not stop incoming ASIC data. At the proposed framed rate, a 100 ms no-drain interval needs about 19.27 MB; this is arithmetic, not tested buffering.

Still uncertain: Allowed host stall, usable buffer depth/bandwidth, reverse flow control, and overrun/recovery policy are undefined. The tutorial starts recording with CLK_IN but does not authorize stopping or restarting it as lossless backpressure.

Close when: Set a bounded stall requirement; size and implement buffering with sustained read/write bandwidth, define loss/backpressure policy, and stress-test a stalled host with sequence/error counters.
