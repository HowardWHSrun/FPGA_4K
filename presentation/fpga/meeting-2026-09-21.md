## Recording and stimulation are separate paths

The FPGA is intended to capture and organize chip outputs, reduce the cable signal count and provide chip-side timing. The downstream platform is intended to receive recording data and forward it toward the PC.

The meeting discussed **88 recording output lines** at the chip/routing-to-FPGA boundary and explicitly stated that stimulation/control inputs are additional. Eighty-eight is not the complete connector pin count. The chip-side pin map must distinguish recording outputs, stimulation inputs, clocks, grounds, supplies and other controls.

For stimulation, the proposed division places waveform storage and packet scheduling downstream. Packets reach the FPGA, which performs any necessary translation and generates the chip-side signals when triggered. Packet format, transfer timing, buffer depth, trigger meaning and overlap with acquisition are not finalized. Simultaneous recording/stimulation was discussed as intended functionality; no validation result was provided.

## Memory and board size

The direction was **not to add separate bulk-data RAM on the FPGA board unless required**. Stream data downstream and store waveforms there. Review inherited memory reservations to reduce area. This does not imply that all FPGA buffering is impossible, nor does it approve deleting configuration flash. The saved BOM contains U2 boot flash; boot configuration is a separate requirement.

The team prioritized getting a functioning system before more aggressive size or power optimization. The 200T was discussed relative to the 35T reference; package, banks, power and pin compatibility still need review.

## Micro-HDMI and downstream adaptation

Two differential recording lanes over the proposed micro-HDMI cable were discussed. The connector is a cable format, not a selected HDMI video protocol. A separate lower-rate return path is needed for stimulation/configuration and possibly a trigger.

J22 / SLVS-EC was considered as a downstream receive route, with HAT/Pmod and SPI/UART possibilities for control. An off-head adapter could split the cable between the selected receive and control ports. Direction, pin accessibility, electrical standards, receiver implementation, common-mode/termination, translator requirements and sustained bandwidth remain open.

The transcript contains speculative interface-rate claims and statements based on AI suggestions. This digest does **not** treat “250 Mb/s” as a universal Pmod/UltraScale+ limit, “1.6 Gb/s per lane” as demonstrated compatibility, or an SLVS-EC connector as automatically usable for arbitrary LVDS. Do not freeze the cable pinout without primary-document and implementation review.

The earlier September 17 path included SFP+ forwarding. The September 21 discussion also mentioned USB/file capture. Host transport and file format therefore remain choices to close, not settled by this presentation.

## Power, grounding and startup

Review all power and I/O voltage domains, decoupling and ground-plane continuity. The transcript's uncertain 1.5/1.8/3.3 V remarks do not define a final bank-voltage map. The intended 32 MHz ASIC clock is documented in the September 18 follow-up; it does not assign the FPGA oscillator frequency.

The saved design has a custom JTAG connector. The meeting requested investigating programming through the downstream platform and cable to avoid a separate bulky connector later. The precise boot/programming/recovery method and signal allocation were not resolved. Do not remove the existing programming path solely on that discussion.

## What the PI review should communicate

Show what each subsystem does, how it is programmed, how recording and stimulation move in opposite directions, and which interface decisions still need joint work. A clear implementation plan matters more than claiming the system already works.

The initial software discussion prioritized recording to a file and inspecting it with Python/MATLAB; live visualization can follow. The presentation's known-pattern link test and closure sequence are **proposed next steps**, not measured results or assigned deadlines.
